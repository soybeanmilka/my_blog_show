自学方法论六条（我的思考）

针对"AI 时代自学新知识"的场景，逐条整理我的六条自学经验。

1 一、先搞明白"学的东西是什么"

学东西之前，先搞明白它底层到底是干什么的，再接触知识会更轻松。

以 AI 产品为例，每发布一个产品：

  • 去看它的官网（定位、宣传口径）
  • 看它的 GitHub（代码、star、issues）
  • 看它的 HuggingFace（模型、榜单、评测）
  • 看它的发布说明/文档（release notes、用法）

把"蒸馏、开源、性能"这类关键词搞明白——即它为了解决什么问题而生——再学具体知识，效率完全不同。

2 二、选方向要功利，扣细节要纯粹

选方向跟着主流走（功利），但深入了解时对细节要纯粹。

  • 选方向功利：现在主流在搞 Agent，就选 Agent 方向，别逆着趋势。
  • 扣细节纯粹：自己去了解它的时候，把细节钻研透彻，不掺功利心。
  • 例子：你是搞 Java 的，但学习计算机底层的时候，要像纯粹研究它一样去学，别想"这对我 Java 有没有用"。

3 三、战略上藐视，战术上重视

第一次认识一个技术时，战略上把它看成一个很小的东西，把它的"壳"去掉；但不要走极端——它发展过程中一定有自己特色，战术上还是要重视。

反过来说：把技术看得太高上大，人会畏难不敢碰。

我的一个思考：有没有可能通过看一个产品的迭代过程（它最开始是为了实现什么目的，后来加了什么）来了解一个东西是干什么的？——用"演进史"当认知路径。

4 四、自下而上 × 自上而下，两条路交替走

学东西有两个方向，上下交替走，路才通。

  • 自下而上：从原理/底层往上，疏通这个东西发展的逻辑。
  • 自上而下：从产品/应用往下，补充它的细节。

⚠️ 陷阱：一直自下而上会很快遇到边际效益——投入大量时间但回报很少。这时应该直接接触它的产品，看它具体在干什么，快速获取细节上的认识。

一开始随便选一条路就行，不必纠结起点。

5 五、尝试把别人教会（费曼学习法）

教别人是最好的教程。给别人讲不清楚的地方，就是自己没搞明白的地方。

  • 讲解过程会暴露逻辑断层：讲着讲着卡住 = 没真正理解。
  • 过程中还能遇到很多同频的人（讲的人、听的人互相筛选）。

6 六、不要太急功近利：绕弯路有时就是捷径

把时间线拉长，不计较当下得失。在当下埋下种子，等待它发芽。

  • 有些弯路其实是在积累关联知识，将来会连成网。
  • 但战线不要拉得太远——种子可以埋，不要种到看不见希望的地方。

7 自测清单

  • 学一个新东西前，能说出"它底层是干什么的"
  • 能区分"选方向"和"扣细节"两种心态
  • 出现边际效益时，知道切换方向去接触产品
  • 能主动给同频的人讲一遍所学
