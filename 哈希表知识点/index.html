哈希表 (Hash Table)

1 核心思想

哈希表通过哈希函数将键映射到桶中，实现 $O(1)$ 平均时间复杂度的插入、删除和查找。

本质：用空间换时间，将遍历查找的 $O(n)$ 降为 $O(1)$。

// 拉链法替代方案，缓存友好
const int N = 20007;  // 质数，开 2~3 倍
int h[N], nil = 0x3f3f3f3f;

int find(int x) {
    int k = (x % N + N) % N;
    while (h[k] != nil && h[k] != x) {
        if (++k == N) k = 0;
    }
    return k;
}

    p[i+1] = p[i] * P;
}
// 子串 [l, r] 的哈希值
ull hash = h[r+1] - h[l] * p[r - l + 1];

// 自定义哈希（pair 等）
struct pair_hash {
    template<class T1, class T2>
    size_t operator()(const pair<T1, T2>& p) const {
        return hash<T1>{}(p.first) ^ (hash<T2>{}(p.second) << 1);
    }
};
unordered_map<pair<int,int>, int, pair_hash> mp;

6 注意事项

  1. 哈希表 vs 数组：值域小（< 10^6）时优先用数组，常数小且无冲突
  2. unordered_map vs map：不需要有序时用 unordered_map，$O(1)$ vs $O(\log n)$
  3. key 不存在时 mp[key] 会插入默认值，判断存在用 count() 或 find()
  4. 避免哈希退化：unordered_map 最坏 $O(n)$，竞赛中可能被卡，可自定义哈希函数
  5. 两数之和类问题，先查再插，避免自己和自己配对
  6. 双射问题（同构、单词模式），必须同时维护两个方向的映射
