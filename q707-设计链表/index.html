题目：不使用内置链表，实现 get、头插、尾插、指定位置插入和指定位置删除。下标从 0 开始，非法查询返回 -1。

1 简要回答

使用一个虚拟头节点 dummyHead_ 和一个记录真实节点数量的 size_。虚拟头节点永远存在，但不存题目数据；真正的第一个节点是 dummyHead_->next。

插入和删除都先找到目标位置的前驱节点，再修改 next：

1
2

插入：prev -> next      变成      prev -> newNode -> next
删除：prev -> target -> next     变成      prev -------> next

size_ 只负责判断下标是否合法，不能让链表像数组一样随机访问。访问第 index 个节点仍然需要从头沿着 next 走过去。

操作时间复杂度
get(index)$O(index)$，最坏 $O(n)$
addAtHead$O(1)$
addAtTail$O(n)$
addAtIndex$O(index)$，最坏 $O(n)$
deleteAtIndex$O(index)$，最坏 $O(n)$

总空间复杂度为 $O(n)$。

2 详细回答

2.1 我的原始思路

我的思考顺序是：

  1. 先构造只包含 val 和 next 的单链表节点。
  2. 写 get(index) 时意识到需要判断越界，于是引入 numbers 记录节点数量。
  3. 看到 index 后联想到 operator[]，又尝试设计一层 NodeList。
  4. 为了实现按下标查找，一度考虑 vector 和 unordered_map。
  5. 随后发现：用现成容器保存节点，实际上绕开了"自己实现链表"的训练目标。
  6. 回到虚拟头节点，但不知道它应该放在哪里、怎样与真实节点连接。

2.2 为什么会卡住

这里其实只需要两层结构：

├── dummyHead_：虚拟头节点

不需要再增加 NodeList，也不需要重载 operator[]。

另外，构造函数里单独写：

1

st_node();

只会创建一个立即销毁的临时对象，并不会初始化链表成员。虚拟头节点必须成为 MyLinkedList 的成员：

1

MyLinkedList() : dummyHead_(new Node()), size_(0) {}

2.3 虚拟头节点到底解决什么

没有虚拟头节点时，头部插入和删除通常要单独修改 head：

1

head -> A -> B

加入虚拟头节点后：

1

dummy -> A -> B -> nullptr

此时 A 也有统一的前驱 dummy。所以在下标 0 处插入、删除，与中间位置的操作完全一样，不需要单独处理真实头节点。

2.4 最重要的定位规则

记住这一句 查询节点时找"目标节点"；插入和删除时找"目标位置的前驱节点"。

假设要在 index = 2 前插入：

1
2
3

dummy -> 0 -> 1 -> 2
                 ↑
               prev

从 dummy 出发移动 index 次，正好到达原下标 1 的节点，也就是插入位置的前驱。

class MyLinkedList {
private:
    struct Node {
        int val;
        Node* next;

        Node(int value = 0, Node* nextNode = nullptr)
            : val(value), next(nextNode) {}
    };

    Node* dummyHead_;  // 永远存在，不计入 size_
    int size_;         // 真实数据节点的数量

public:
    MyLinkedList()
        : dummyHead_(new Node()), size_(0) {}

    ~MyLinkedList() {
        Node* cur = dummyHead_;
        while (cur != nullptr) {
            Node* next = cur->next;
            delete cur;
            cur = next;
        }
    }

    int get(int index) {
        if (index < 0 || index >= size_) {
            return -1;
        }

        Node* cur = dummyHead_->next;
        for (int i = 0; i < index; ++i) {
            cur = cur->next;
        }
        return cur->val;
    }

    void addAtHead(int val) {
        addAtIndex(0, val);
    }

    void addAtTail(int val) {
        addAtIndex(size_, val);
    }

    void addAtIndex(int index, int val) {
        if (index < 0) {
            index = 0;
        }
        if (index > size_) {
            return;
        }

        Node* prev = dummyHead_;
        for (int i = 0; i < index; ++i) {
            prev = prev->next;
        }

        prev->next = new Node(val, prev->next);
        ++size_;
    }

    void deleteAtIndex(int index) {
        if (index < 0 || index >= size_) {
            return;
        }

        Node* prev = dummyHead_;
        for (int i = 0; i < index; ++i) {
            prev = prev->next;
        }

        Node* target = prev->next;
        prev->next = target->next;
        delete target;
        --size_;
    }
};

3 知识扩展

3.1 三个必须保持的不变量

  1. dummyHead_ 永远存在，而且不计入 size_。
  2. size_ 必须等于真实数据节点的数量。
  3. 最后一个真实节点的 next 必须是 nullptr。

3.2 易错点

边界区别 addAtIndex 允许 index == size_，因为这代表尾插；但 get 和 deleteAtIndex 要求 index < size_。

  • 插入、删除成功后才修改 size_。
  • 删除前先保存 target，重新连接后再 delete target。
  • 虚拟头节点不是下标 0；真实下标 0 是 dummyHead_->next。
  • vector 和哈希表可以加速按下标访问，但那已经改变了题目要求的数据结构实现方式。

3.3 还能怎样优化

如果额外维护一个尾指针，可以把 addAtTail 优化为 $O(1)$。但删除最后一个节点时也必须正确更新尾指针，维护成本更高。当前版本先把"虚拟头节点 + 前驱定位"掌握牢更重要。

3.4 自测

  • 能解释为什么 size_ 不能实现随机访问
  • 能画出虚拟头节点与真实头节点的关系
  • 不看答案写出指定位置插入
  • 说清楚插入和删除的合法下标范围为什么不同
