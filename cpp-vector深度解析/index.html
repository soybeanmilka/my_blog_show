1 一、底层原理

vector 是动态数组，底层是一段连续的内存空间。

1

3
4

│ 0 │ 1 │ 2 │ 3 │   │   │   │   │
└───┴───┴───┴───┴───┴───┴───┴───┘
  size = 4          capacity = 8
  • size：当前元素个数
  • capacity：实际分配的内存容量
  • 当 size == capacity 时再插入，会触发扩容

2 二、扩容机制

2.1 扩容过程

  1. 重新分配一块更大的内存（通常 1.5 倍或 2 倍）
  2. 把旧元素全部拷贝/移动到新内存
  3. 释放旧内存
  4. 更新内部指针

GCC 是 2 倍扩容，VS 是 1.5 倍扩容。

2.2 时间复杂度

  • 均摊 O(1)：大部分插入是 O(1)，偶尔扩容 O(n)，平均下来还是 O(1)

2.3 避免扩容的方法

1
2

vector<int> v;
v.reserve(1000);  // 提前分配 1000 容量，避免中途扩容

3 三、迭代器失效

3.1 什么情况会失效？

1. 插入操作（push_back, insert）

  • 触发扩容 → 所有迭代器、引用、指针全部失效
  • 没扩容 → 插入位置之后的迭代器失效

2. 删除操作（erase, pop_back）

  • 删除位置及之后的迭代器失效
  • end() 永远失效

3. swap / clear

  • swap：两个 vector 的迭代器互换
  • clear：所有迭代器失效，但 capacity 不变

3.2 经典坑：erase 遍历

// ❌ 错误写法：it 失效后 ++ 是未定义行为
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == target) v.erase(it);
}

// ✅ 正确写法：erase 返回下一个有效迭代器
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == target) {
        it = v.erase(it);
    } else {
        ++it;
    }
}

4 四、常用操作

4.1 构造函数

1
2
3
4
5

vector<int> v1;                // 空
vector<int> v2(10);            // 10 个元素，默认 0
vector<int> v3(10, 5);         // 10 个 5
vector<int> v4{1, 2, 3, 4};    // 列表初始化
vector<int> v5(v4.begin(), v4.end());  // 迭代器范围

4.2 卡点：构造时填了初值，push_back 从哪开始

我的疑问：vector<int> v(5, 0) 之后再 push_back，新元素是不是插不进"前面"？

是的——v(n, 0) 是"先定长填 n 个 0"，size 已经是 n；之后 push_back 永远追加在末尾（下标 n 开始），不会从头插：

1
2
3
4
5

vector<int> v(5, 0);   // {0,0,0,0,0}，size = 5
v.push_back(7);        // {0,0,0,0,0,7}，7 在下标 5（第 6 位）

vector<int> w;         // 空，size = 0
w.push_back(7);        // {7}，7 在下标 0（第 1 位）

两种思路二选一，别混：

目的正确写法
动态追加（数量不定）初始化为空 vector<int> v;，只 push_back
固定长度按下标填vector<int> v(n, 0); 然后 v[i] = x;（下标改，不是 push_back）

常见坑：先 v(n, 0) 又 push_back → 得到 n+1 个元素、前 n 个全是 0，数据全挤到后面；v[i] = x 越界是未定义行为（不会自动扩容，可能直接崩）。

4.3 增删改查

v.push_back(10);     // 尾部插入 O(1) 均摊
v.pop_back();        // 尾部删除 O(1)
v.insert(it, 20);    // 指定位置插入 O(n)
v.erase(it);         // 删除指定位置 O(n)
v.clear();           // 清空所有元素，capacity 不变
v.shrink_to_fit();   // 释放多余空间，capacity = size

5 五、内存管理细节

5.1 clear() 不释放内存

1
2

vector<int> v(1000);
v.clear();          // size = 0，但 capacity 还是 1000

5.2 真正释放内存的方法

1
2
3
4
5
6

// 方法1：swap 空 vector
vector<int>().swap(v);

// 方法2：shrink_to_fit（C++11）
v.clear();
v.shrink_to_fit();

5.3 用 reserve 优化性能

知道大概要存多少元素时，提前 reserve：

1
2
3
4
5

vector<int> v;
v.reserve(10000);  // 一次分配到位
for (int i = 0; i < 10000; i++) {
    v.push_back(i);  // 不会触发扩容
}

6 六、常见坑点总结

坑点说明
迭代器失效插入删除后旧迭代器不能再用
引用失效扩容后所有引用都悬空
[] 越界不检查，越界是 UB，用 at() 更安全
resize vs reserveresize 改 size，reserve 只改 capacity
空 vector 调用 front/backUB，先判断 empty
vector<bool>不是真正的 vector，是位压缩的特殊实现，尽量别用

操作时间复杂度

尾插 push_backO(1) 均摊
尾删 pop_backO(1)
中间插入O(n)
中间删除O(n)
扩容O(n)
