Codex / Cloud Code 接 DeepSeek API：能接吗？效果差多少？

1 简要回答

  • Codex 能接 DeepSeek，三行配置的事
  • Cloud Code（Google）基本不能接，绑定自家生态
  • 效果差别：外壳（工具本身）一样，上限由模型决定；GPT-5-Codex 为 coding agent 特调，DeepSeek 是通用模型，复杂任务差距明显、简单任务够用且便宜

2 我的想法 / 卡点

之前一直以为这些工具只能用自己的模型，聊完才知道：

  • Codex 2026 年 6 月官方宣布支持第三方模型，从"OpenAI 专用客户端"变成"模型中立的编码代理平台"
  • 我的困惑点是"DeepSync 是什么"——其实是语音识别把 DeepSeek 听错了
  • “Cloud Code 源码泄露导致 React/Reason 流行"这个说法也记错了：泄露的是 Claude Code（Anthropic），不是 Google 的 Cloud Code

3 详细回答

3.1 Codex 接入 DeepSeek（可行）

~/.codex/config.toml 加 provider 定义：

1
2
3
4

[model_providers.deepseek]
name = "DeepSeek"
base_url = "https://api.deepseek.com/v1"
env_key = "DEEPSEEK_API_KEY"

命令行走 codex --provider deepseek --model deepseek-coder 切换。Kimi、GLM、Qwen、Ollama 同理。

坑：

  • Codex 2026 年 2 月起默认走 Responses API，第三方接口大多只有 Chat Completions，需设 wire_api = "chat"，否则报流式/格式错误
  • 桌面端接 DeepSeek 需要两层本地代理（模型名映射 + Responses→Chat 转换），社区有现成方案
  • provider ID 区分大小写，模型名前缀写错会被静默忽略走 fallback

3.2 Cloud Code 接入 DeepSeek（基本不可行）

  • Cloud Code（IDE 插件）绑定 Google 生态，不开放自定义模型
  • Gemini CLI（已开源）原生只认 Gemini；需"魔改版"或 LiteLLM 代理才能接 DeepSeek
  • 且 Gemini CLI 免费版 2026-06-18 已停用，个人用户迁移到 Antigravity CLI

3.3 效果差别：外壳一样，上限由模型决定

场景效果
简单任务、补全、小修改DeepSeek 够用，价格低一个量级，性价比最高
复杂重构、多文件修改GPT-5-Codex 工具调用准确率高，DeepSeek 出错率明显上升
多步 Agent 长任务专用模型规划更稳，DeepSeek 容易跑偏

结论：日常小活用 DeepSeek 省钱，大活切回专用模型。Codex 支持多 provider 随时切，opencode 本身 75+ 模型随便换。

3.4 彩蛋：源码泄露事件的真相

  • 2026-03-31，Anthropic 的 Claude Code 因 npm 包遗留 59MB source map（cli.js.map），51.2 万行 TypeScript 全曝光（第二次同原因泄露）
  • 大家因此看到：终端 UI 用 React+Ink、Bun 运行时、40+ 工具模块、权限分层
  • React（2013 年）/ ReAct（2022 年论文）不是泄露"导致"的，泄露只是让大家看到了顶级 Agent 的工程实现，引发讨论和借鉴

4 知识扩展

  • DeepSeek API 完全兼容 OpenAI 协议，官方文档有 coding agents 接入指南
  • Codex config.toml 三级配置：用户级（~/.codex/config.toml）→ 项目级（.codex/config.toml）→ 命令行参数，优先级递增
  • 环境变量方式（OPENAI_BASE_URL）只能配一个 provider，config.toml 支持多 provider 并存切换
